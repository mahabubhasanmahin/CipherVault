What CipherVault is

CipherVault encrypts text and files entirely inside your browser before anything touches a server. It was built as a university project to demonstrate practical, hands-on use of symmetric and asymmetric cryptography — AES-256-GCM, RSA-OAEP, and ChaCha20-Poly1305 — in a real, working application rather than just in theory. That means key derivation, authenticated encryption, JWT-based auth, and a genuinely zero-knowledge storage design: the server only ever sees ciphertext and metadata, never your plaintext or your passphrase.

How it's built

  • Client-side encryption — AES-GCM and RSA-OAEP run through the browser's native Web Crypto API; ChaCha20-Poly1305 runs through libsodium.js, since it isn't in Web Crypto yet.
  • Personal vault — save, list, and delete your encrypted items, each tagged with its algorithm and creation date.
  • Expiring share links — send an item to someone else via a time-limited token; the passphrase or private key still never touches the server.
  • Admin dashboard — usage stats plus every registered user and vault item, for the account holder managing the deployment.
  • Auth — JWT sessions with bcrypt-hashed passwords, backed by MongoDB.

A note on scope

  • This is an academic project, built to demonstrate cryptographic concepts end-to-end — not a hardened production service.
  • For production use it would still need rate limiting, refresh tokens, enforced HTTPS, and stronger private-key handling.
  • There is no password or passphrase recovery by design — losing either means losing the data.
